// fleeting design system

A sharp, token-driven component system built for verification-first interfaces

Fleeting's design system is a catalogue of 53 shadcn/ui-styled components — buttons, forms, overlays, data display, feedback — built on one set of HSL design tokens and shared across a light and a true-black dark theme. This site documents what's actually implemented: the tokens, the components, the states, and the gaps still open.

What this is for

This system exists to give every screen in Fleeting — session boards, attempt inspectors, verification reports — the same visual grammar, so an "attempt" always looks like an attempt and a "verified" badge always means the same thing wherever it appears. It started as a single self-contained HTML file with all 53 components inline; this site is that same catalogue, reorganized into foundations, components, themes and usage guidance so it reads as a reference rather than a long scroll.

Visual language, in five traits

Sharp geometry

Zero corner radius everywhere, with two named exceptions: avatars and the skeleton loading circle.

True-black dark mode

Dark mode is pure black (0% lightness), not the softer dark-gray most shadcn systems default to — a deliberate, high-contrast choice.

Two typefaces, one rule

Inter for interface text. JetBrains Mono only for identifiers, code, and data — session names, costs, timestamps.

Token-driven color

Almost every color is hsl(var(--token)), so both themes repaint from one source — with two documented exceptions, see Principles.

Borders over shadows

Flat surfaces get a 1px border and no shadow. Shadow is reserved for surfaces that float above the page.
