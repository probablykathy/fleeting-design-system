Accessibility

An honest inventory, not a checklist claiming compliance. Every item below was verified against the actual markup and CSS — nothing here is assumed or aspirational.

Already implemented
Global focus-visible ringOne shared :focus-visible{outline:2px solid hsl(var(--ring))} rule in base.css, applied consistently — no per-component ring styling to drift.
Native interactive elementsButtons, inputs, textareas and the native select are real <button> / <input> / <select> elements — keyboard focus and activation work with zero extra code.
Native disabled stateDisabled buttons use the real disabled attribute, correctly removed from the tab order and announced by assistive tech.
High base contrastPrimary text against background is very high contrast in both themes by construction (near-black on white; near-white on true black) — comfortably passes WCAG AA/AAA for normal text.
Needs improvement
Custom checkbox, switch, radio and toggle are not keyboard-operableThey're plain <span> elements driven by onclick, with no tabindex — a keyboard-only user cannot reach or activate them at all today, not even with the wrong announcement; they're simply skipped.
No ARIA roles or state on custom controlsNo role="checkbox"/"switch"/"radio", no aria-checked — a screen reader has nothing to announce for these controls beyond "clickable".
Menu items and tabs carry no ARIA relationship.menu-item is a plain <div> (no role="menuitem"); .tabstrig/.tabpanel have no role="tab"/"tabpanel" or aria-selected linking them.
No Escape-to-close on any overlayDialog, Alert Dialog, Drawer, Dropdown, Popover, Select and Context Menu all close only via outside-click or an explicit button — never via the Escape key, which is the expected keyboard affordance for a dismissible surface.
Icon-only buttons have no accessible nameThe .btn-icon example ships with no visible text and no aria-label — a screen reader announces an unlabeled button.
Recommended before production
Real keyboard operability for every custom controlCheckbox, Switch, Radio, Toggle, Menu items, Tabs and Accordion triggers need focus + Enter/Space activation — either by rebuilding on native elements or by adding tabindex, key handlers, and ARIA roles/state.
Focus trapping in modal surfacesDialog and Alert Dialog currently let keyboard focus tab straight out into the page behind them — a real focus trap is needed before either ships in a live product.
Escape-to-close on every dismissible overlayA single shared keydown handler would cover Dialog, Drawer, Dropdown, Popover, Select, Context Menu and Command consistently.
A real contrast auditPrimary text passes by eye, but --muted-foreground against various backgrounds hasn't been run through an actual contrast checker (e.g. axe or a WCAG contrast tool) — do that before relying on the "looks fine" assessment above.
Mandatory labeling for icon-only buttonsEvery icon-only button instance going forward should require a visible label or an aria-label — this demo catalogue is fine for design exploration, but the interaction layer isn't production-accessible yet.
