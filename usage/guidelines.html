Guidelines

Decision guidance for components that are easy to confuse — grounded in the actual behavior each one implements, not a general theory of when dialogs are good.

Dialog vs. Alert Dialog vs. Drawer

All three are overlays. What differs is how they can be dismissed and what they're for.

Dialog

Non-destructive, informational. Dismissible by clicking outside. Use for anything the user can safely back out of without a decision.

Alert Dialog

Blocking. Requires an explicit choice — no dismiss-by-clicking-outside. Use only when an action needs confirmation before it proceeds (closing an attempt, deleting something).

Drawer

Slide-over panel for inspecting or editing a record in place, without leaving the surrounding context. Use when the user needs to keep the list/board behind it visible.

Select vs. Native Select vs. Command

All three let a user pick from a list — for different reasons.

Select

Custom-styled to match the visual system exactly. Currently has no keyboard/screen-reader support (see Accessibility) — use when visual consistency matters most and the list is short.

Native Select

A real <select> — full native keyboard and assistive-tech support for free, less control over exact appearance. The safer default whenever accessibility matters more than pixel-perfect styling.

Command

A searchable palette for a large or action-oriented list. For finding and launching something, not for picking one value in a form.

Accordion vs. Collapsible

Accordion

Multiple grouped sections, each independently expandable. Use when there are several related, organized panels.

Collapsible

The same open/close mechanic, but a single panel with no grouping. Use for one optional block of detail (e.g. "show environment details").

Popover vs. Hover Card vs. Tooltip

Tooltip

A single-line hint on hover. No interactive content, ever.

Hover Card

Richer preview content on hover — still not interactive while triggered by hover.

Popover

Click-triggered, and can contain real interactive content (the cost-breakdown example elsewhere in the catalogue).

Direction — RTL / LTR

Reclassified here from the component catalogue: this is a document-level text-direction behavior, not a reusable UI component.

Verified attempt-2 · middleware split

Setting dir="rtl" on a container flips its flex-direction via a single rule (.dir-demo[dir="rtl"]). This is demonstrated on one small block only — RTL has not been verified across the other 52 components, so treat it as an exploratory capability, not a guaranteed one, until it's checked component by component.
