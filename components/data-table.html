Data Table

A table with sortable-styled column headers and a user avatar+name cell pattern — currently incomplete: no rows are rendered and sorting doesn’t work.

Anatomy

[table#dataTable] [thead] — Attempt, User, [th.sortable Status], [th.sortable Cost] [tbody] — empty in the current source

Live preview

Attempt User Status Cost

The table above is exactly what the current source renders — headers only, no rows. See Interaction notes.

Class reference

ClassWhat it does
th.sortableAdds a pointer cursor and a chevron icon to a header cell.
th.sortable.asc / .descWould rotate and darken the chevron to show sort direction — never applied by any script.
.dt-userIntended layout for an avatar + name pairing inside a body cell (small 24px avatar).

Interaction notes

This is a known, documented implementation gap, not a design choice: the source markup declares data-sort attributes and sortable-styled chevron icons on the Status and Cost headers, and defines .dt-user styling for an avatar+name cell — but <tbody> is empty and no script anywhere populates rows, reads data-sort, or handles a click on a sortable header. Clicking "Status" or "Cost" currently does nothing. This documentation intentionally does not add that functionality — it documents the gap rather than papering over it.

Usage

When to use

Not yet — wait until row population and sort handling are implemented before using this in a real screen.

When not to use

Anywhere a working sortable table is actually required today; use the plain Table component with static rows instead until this is completed.

Accessibility

Cannot be evaluated meaningfullyWith no rows and no working sort, there’s no real interaction to audit yet. Once implemented, sortable headers will need aria-sort and a keyboard-operable trigger (currently they’re plain <th> cells with a CSS cursor, not buttons).
