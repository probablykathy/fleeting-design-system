Interaction notes

This replaces the source’s previous single confirm/cancel Alert Dialog entirely — there is no longer a bare "close this attempt?" confirmation, and its old ids (#alertDialogOverlay, #confirmAlertDialog, #cancelAlertDialog) no longer exist anywhere in the source or this site. The current implementation is three independent overlays: Progress starts a setInterval that fills the bar with random increments up to 100% and can be cancelled mid-way; Success is a static confirmation with one dismiss action; Failure offers Cancel or Retry, and Retry closes the failure dialog and re-opens the Progress flow from zero.

Usage

When to use

A single blocking outcome that truly needs the user’s attention before continuing (an async operation’s result).

When not to use

Anything dismissible by clicking outside — that’s Dialog, not this.

Accessibility

No focus trap or EscapeSame gap as Dialog — tabbing escapes the modal, Escape does nothing.
Progress bar isn’t announcedThe animated .progress fill has no role="progressbar" or aria-valuenow — a screen reader gets no update as it fills.
