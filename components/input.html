States

The states above are the actual six shown together in the source’s own Input demo — .is-typing and .is-active are visually identical (both apply the same ring), so the source treats them as one state styled two ways in markup, not two distinct visual outcomes.

Class reference

ClassWhat it does
.inpBase field: 32px height, 1px input border, no radius.
.is-typing / .is-activeRing-colored border + soft box-shadow ring — identical declarations.
.is-errorDestructive-colored border; ring turns destructive-colored on focus instead of the default ring color.
:hover:not(:disabled):not(:focus)Border tints 50% toward the ring color — a subtle hint, not a full ring.
:disabled50% opacity, cursor:not-allowed.

Interaction notes

Purely CSS — .is-typing, .is-active and .is-error are all static demonstration classes in this source, not states a real typing session would toggle automatically. A production field would need JS (or :focus alone) to move between these, which isn’t wired here.

Usage

When to use

Free-text entry — filtering, naming, short-answer fields.

When not to use

Fixed choices from a list — use Select or Native Select instead.

Accessibility

Native element — goodA real <input>, so it’s keyboard-focusable and works with labels, autofill, and screen readers by default.
Error state has no ARIA wiringThe error example sets a visual red border and a hint below it, but the input has no aria-invalid and the hint text isn’t associated via aria-describedby — a screen reader user won’t hear the error.

Code

<input class="inp is-error" value="Typing"> <span class="hint" style="color:hsl(var(--destructive))">Error message</span>
