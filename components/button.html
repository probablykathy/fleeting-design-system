Button

The primary trigger for a command. Every clickable action in the system — promoting an attempt, closing a session, confirming a destructive choice — reads through one of Button's six style variants, so intent stays visually consistent everywhere a person can click something.

Anatomy

[button.btn.btn-<variant>] [icon svg — optional, leading or trailing] [label text] — icon-only (.btn-icon): label is omitted visually, icon only, square

Live preview

Variants

Six style variants, all sharing the same .btn base.

.btn-defaultThe primary action on a screen — one per view, typically.
.btn-outlineA secondary action, visually equal weight to the content around it.
.btn-secondaryA lower-emphasis alternative to outline; filled but muted.
.btn-ghostNo border until hovered — for the least prominent action in a group.
.btn-destructiveIrreversible or high-consequence actions only.
.btn-linkReads as inline text — for the lowest-emphasis navigational action.

Sizes

.btn-sm28px
.btn (no size class)32px
.btn-lg36px
.btn-icon32×32px square

States

rest
hover (approximated — hover the live preview above to see the real transition)
disabled — native disabled attribute, 50% opacity
focus-visible — tab to the live preview to see the real ring

Only rest and disabled are real, distinct CSS states today. Hover and focus above are staged approximations for side-by-side comparison — try the live preview section for the genuine interaction.

Class reference

ClassWhat it does
.btnBase: layout, height (32px), padding, font, transparent border. Always required.
.btn-defaultPrimary fill — --primary background, --primary-foreground text.
.btn-outlineBackground surface color with a visible --input border.
.btn-secondary--secondary fill, muted-weight alternative to outline.
.btn-ghostTransparent until hover, then --accent background.
.btn-destructive--destructive fill for irreversible actions.
.btn-linkNo background or height constraint; underlined --primary-colored text.
.btn-sm28px height, tighter padding and font-size.
.btn-lg36px height, wider padding, 13px font-size.
.btn-iconSquare (32×32px), zero horizontal padding — for icon-only buttons.
:disabledNative pseudo-class — 50% opacity, cursor:not-allowed.

Interaction notes

Button has no JavaScript of its own — every state above is pure CSS on a native <button> element. Hover and active feedback are only implemented for .btn-ghost today (a background fade on hover); the other five variants have no explicit :hover rule in components.css, so they render visually static until clicked. Worth flagging as a gap rather than assuming it was intentional.

Accessibility notes

Native element — goodA real <button>, so it's keyboard-focusable and Enter/Space-activatable for free, with no ARIA needed.
Native disabled — goodUses the real disabled attribute, which correctly removes it from the tab order and announces its state to screen readers.
Focus ring — goodInherits the shared, system-wide :focus-visible ring rather than a per-component style — consistent everywhere.
Icon-only buttons — needs workThe .btn-icon example above has no visible text and no aria-label in the current markup — a screen reader announces it as an unlabeled button. See Accessibility.
