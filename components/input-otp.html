Input OTP

Six single-digit boxes for a one-time verification code, with auto-advance between digits and a working verify flow against a fixed code.

Anatomy

[div.otp#otpBox] [input maxlength=1] × 6 [button — Verify] [span#otpMsg — result message]

Live preview

Try any code, then 1 2 3 4 5 6 — the correct one is hardcoded in the demo script.

States

rest
.shakebrief horizontal shake animation + destructive borders on wrong code
.successchart-ok colored borders on the right code

Class reference

ClassWhat it does
.otpFlex row of fixed-width single-character inputs, mono font.
.otp.shakeRuns a 400ms horizontal shake keyframe and reddens every box’s border.
.otp.successGreens every box’s border (via --chart-ok).

Interaction notes

Typing a digit auto-focuses the next box; Backspace on an empty box moves focus back one. Verify joins all six values and compares them to a hardcoded string ("123456") in the page script — there is no real backend check. A correct code adds .success and shows "✓ verified"; a wrong one clears every box, re-triggers the .shake animation, and refocuses the first box. Entering fewer than 6 digits and clicking Verify shows "Enter all 6 digits" without shaking.

Usage

When to use

A short numeric verification code with a known, fixed length.

When not to use

Any longer or alphanumeric code — the fixed-width boxes and single-character inputs aren’t built for that.

Accessibility

Six unlabeled inputsEach box is a bare <input maxlength="1"> with no aria-label — a screen reader announces "edit text" six times with no indication this is one 6-digit code.
Result message isn’t announcedThe verify result (#otpMsg) changes color and text but has no aria-live region, so screen reader users aren’t told the outcome unless they navigate to it manually.

Code

<div class="otp"><input maxlength="1"><input maxlength="1"></div> <button class="btn btn-outline btn-sm">Verify</button>
