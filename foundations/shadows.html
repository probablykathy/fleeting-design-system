Shadows

A deliberate two-tier rule: flat, in-page surfaces carry no shadow at all — separation comes from the 1px border. Shadow appears only on surfaces that float above the page.

01

Flat — no shadow

Card, Button, Input, Badge, Alert, Table. Separation is border-only.

No shadow

Card, Button, Input…

Border-only separation from the page.
02

Shadow scale

Four named tokens, extracted verbatim from the four elevation values already in use — no new values invented. Each row: visual example, token, actual value, typical usage.

Small
Small --shadow-sm
0 4px 14px rgba(0,0,0,.15)
Typical usage: Tooltip — the lightest lift, for a single-line hint.
Medium
Medium --shadow-md
0 8px 24px rgba(0,0,0,.12)
Typical usage: Select — a dropdown list floating over its trigger.
Large
Large --shadow-lg
0 10px 30px rgba(0,0,0,.15)
Typical usage: Menu, Popover, Hover Card, Toast, Navigation Menu panel — anchored surfaces with real content, floating further than a hint.
Extra Large
Extra Large --shadow-xl
0 20px 50px rgba(0,0,0,.25)
Typical usage: Dialog — the highest surface in the system, centered over a dimmed scrim.
03

Elevation hierarchy

The intended order the four tokens read in, lightest to heaviest.

Tooltip — --shadow-sm
↓
Select — --shadow-md
↓
Menu / Popover — --shadow-lg
↓
Dialog — --shadow-xl

Each step corresponds to how far the surface floats above the page and how much it competes for attention — a hint (Tooltip) sits closest to the page; a surface that blocks interaction with everything behind it (Dialog) sits highest. Hover Card, Toast, and the Navigation Menu panel share --shadow-lg with Menu/Popover — they're peers in the hierarchy, not a fifth step.

04

Literal values intentionally retained

Two shadows in the source are close to a token but not identical — left as literals rather than forced onto the nearest match, which would have silently changed their rendered value.

ComponentActual valueClosest tokenWhy not tokenized
Slider tooltip0 4px 12px rgba(0,0,0,.15)--shadow-sm (0 4px 14px)2px less blur — a distinct, deliberately lighter touch for a value that tracks the thumb continuously.
Card .hoverable0 10px 24px rgba(0,0,0,.1)--shadow-lg (0 10px 30px)Less blur and a lower alpha (.1 vs .15) — a subtler hover lift than an anchored overlay's shadow, appropriate since a card sits flat on the page until hovered.

Also excluded, for a different reason: the box-shadow: 0 0 0 3px … rules on Input's focus/typing/error states. Those aren't elevation shadows at all — they're a spread-only ring/glow effect already built from color tokens, so they were never candidates for this scale.
