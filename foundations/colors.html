Colors

Every color in the system is an HSL custom property, referenced as hsl(var(--token)) — never a hardcoded value. Each swatch below shows its light value and its dark value side by side, independent of the site's current theme toggle, so both are visible at once.

01

Background & surface

--background
L 0 0% 100% · D 0 0% 0%
--foreground
L 240 10% 3.9% · D 0 0% 92%
--card
L 0 0% 100% · D 0 0% 6%
--card-foreground
same as --foreground
--popover
L 0 0% 100% · D 0 0% 6%
--popover-foreground
same as --foreground

05

Chart

Defined in both themes. As of the latest source sync, all four are actually consumed: --chart-info by the chart bars, line graph and one avatar fill; --chart-ok/--chart-warn/--chart-claim by the new status Badges and Alert variants (Approved/soft-success tones, Pending/warning tones, Submitted/claim tones) and the grouped/stacked Chart series. Previously three of these four were unused — that's no longer accurate and has been corrected here.

--chart-ok
L 158 64% 32% · D 158 55% 50%
--chart-warn
L 32 90% 40% · D 32 85% 60%
--chart-info
L 217 80% 56% · D 217 85% 70%
--chart-claim
L 255 60% 55% · D 255 75% 76%
06

Status badge colors — not tokens

Three of the ten new status badges (Discovery, In Review, Issue) don't go through a custom property at all. Documented here exactly as implemented, not converted to tokens yet — see Principles for why this is flagged as a known exception rather than fixed silently.

.badge-discovery
L hsl(320 70% 45%) · D hsl(320 80% 72%)
.badge-review
L hsl(38 75% 38%) · D hsl(45 90% 65%)
.badge-issue
L hsl(0 65% 40%) · D hsl(0 70% 68%)

Each of these three sets its own light-mode HSL literal directly in components.css, then overrides just the text color for dark mode via a dedicated :root[data-theme="dark"] .badge-x rule — the first per-component dark override in the system; every other color swap happens through the token blocks alone. The other seven status badges (Approved, Submitted, Publishing, Pending, Failed, Draft, Archived) all route through existing tokens (--chart-ok/claim/info/warn, --destructive, --muted-foreground) and need no such override.
