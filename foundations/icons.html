Icons

Lucide is the approved icon library for this design system — a single, consistent set of stroke-based, MIT-licensed icons at github.com/lucide-icons/lucide. Every icon shown on this page is a real, unmodified Lucide asset, downloaded verbatim and stored locally at assets/icons/lucide/.

01

Why Lucide

The 53 existing components already hand-draw their icons as thin, rounded-stroke line art — a handful of the Fleet's own trigger/close/chevron glyphs already look close to Lucide's own grammar by coincidence. Lucide formalizes that: one open-source, actively-maintained, MIT-licensed set covering the vocabulary a product like this needs (navigation, form, status, media), with a genuinely scalable pure-vector format that needs no build step or icon font to use.

02

Icon style

Lucide ships one style family: stroke-based outline icons. There is no separate "filled" set of the same glyphs.

search
settings
user

Regular (outline) is the default and, for most icons, the only option. Reach for a different treatment only when Lucide itself publishes a distinct, appropriately-named icon for the state you need — for example check vs. circle-check for a plain confirmation vs. a completed/success state, not by inventing a "filled" version of an icon Lucide only draws as an outline. Never fabricate a solid-fill variant of a Lucide glyph — that would no longer be an unmodified Lucide asset.

03

Sizes

Three primary sizes. Because Lucide icons are pure vector (one 24×24 viewBox, no per-size pixel grid), any size is just the width/height attribute — there's no separate source asset per size.

20px

16pxInline with 11.5–12.5px body/label text — badge icons, dense table rows, input-adjacent icons.

04

Stroke

Every Lucide icon in this library uses its shipped default: stroke-width="2", stroke-linecap="round", stroke-linejoin="round", fill="none". Keep 2px as the default everywhere. The one sanctioned exception: a specific component with unusually small icon real estate may need a heavier stroke (e.g. 2.5px at 16px) to stay legible — treat that as a deliberate, documented per-component override, not a system-wide change.

05

Color

Every icon uses stroke="currentColor" — no icon carries its own color. It inherits whatever text color its container has, which is how the same markup repaints correctly across both themes.

Light
Dark

No separate icon color palette exists or should be introduced. An icon that needs to read as "success" or "destructive" gets that meaning from whichever existing color token its container already uses (--chart-ok, --destructive, etc.) — see the Status icon pattern below — never from a new icon-specific color variable.

07

Usage guidelines

Use icons consistentlyThe same action or concept should always use the same icon across the system — don't let two different glyphs both mean "delete."
Do not mix icon librariesLucide is the only approved source. Don't hand-draw a new icon or pull one from another set when a Lucide icon already covers the need.
Keep sizes appropriate to the controlMatch the icon size to its context — 16px inline with small text, 20px in standard controls, 24px for standalone or larger moments. Don't drop a 24px icon into a dense 16px table row.
Pair with a label when meaning isn't universalChevrons, close (×), and a plain checkmark are broadly understood on their own. Anything more specific (Filter, Refresh, a status glyph) should carry visible text or a tooltip alongside it unless the surrounding context already makes it obvious.
Icon-only controls must have an accessible nameAn icon with no visible text still needs an aria-label (or equivalent) naming the action — see Accessibility below and the Icon-only button pattern.
Don't use icons as pure decoration where they could confuseAn icon implies meaning. If it doesn't actually correspond to an available action or a real state, leave it out rather than risk a user acting on it.
08

Accessibility

Decorative icons — hide them from assistive techWhen an icon sits next to visible text that already says the same thing (e.g. a Search icon beside the word "Search"), mark the <svg> with aria-hidden="true" so a screen reader doesn't announce it redundantly.
Meaningful icons need an accessible nameWhen the icon is the control's only content, the control itself (usually a <button>) needs aria-label="…" naming the action in words — "Settings," not "gear icon."
Color is never the only signalA status icon's color reinforces meaning; the icon's shape (circle-check vs. circle-alert vs. circle-x) must carry the meaning on its own for anyone who can't distinguish the color.
Currently a documentation-only guaranteeThis page's own examples follow the rules above, but see Usage → Accessibility — several existing components' icon-only buttons predate this page and don't yet carry an aria-label. That gap is tracked there, not silently claimed as fixed here.
09

Developer usage

The simplest integration that fits this project: no npm package, no build step, no icon font — copy the real SVG markup and inline it.

<!-- Copy straight from assets/icons/lucide/{name}.svg, or from lucide.dev --> <svg width="20" height="20" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"> <path d="m21 21-4.34-4.34" /> <circle cx="11" cy="11" r="8" /> </svg>

Every icon used anywhere in this project should trace back to a file under assets/icons/lucide/ — that folder is the local mirror of record. To add an icon not yet in that folder: find its exact name on lucide.dev/icons, download the real SVG (not a redrawn approximation), save it into assets/icons/lucide/{name}.svg unmodified, then inline its markup at the point of use exactly as shown above — set width/height to 16, 20, or 24, leave stroke="currentColor" alone so it themes automatically, and never edit the <path>/<circle> data itself.
